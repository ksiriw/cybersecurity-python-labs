# ЛР №4: інтеграція з NVD API та автоматизоване тестування

Консольна утиліта шукає запис про вразливість у National Vulnerability Database (NVD) за ідентифікатором CVE. Вона перевіряє відповідь, вибирає оцінку CVSS v3.1 і застосовує правило свого варіанта, а потім друкує JSON-звіт.

## Варіант і правило

Варіант 1 (номер береться з `shared/student.py`): **мережевий вектор атаки**.

Рішення `review` приймається, якщо в одній і тій самій вибраній оцінці CVSS v3.1 виконуються обидві умови:

- `baseScore >= 7.0`;
- `cvssData.attackVector == "NETWORK"`.

`attackVector` описує, звідки можна здійснити атаку. `NETWORK` означає, що атакувати можна віддалено через мережу. Інші значення: `ADJACENT_NETWORK`, `LOCAL`, `PHYSICAL`.

Вибір оцінки: перша оцінка з `type="Primary"`, а якщо такої немає, то перша в списку `cvssMetricV31`.

## Встановлення

Команди виконуються з кореня репозиторію в активованому віртуальному середовищі (Python 3.12+).

```bash
pip install -r requirements.txt
```

## Запуск

Локальний режим, без мережі, на синтетичній відповіді:

```bash
python -m labs.lab04.main --cve CVE-2099-10001 --input labs/lab04/data/nvd_sample.json
```

Один запит до NVD:

```bash
python -m labs.lab04.main --cve CVE-2021-44228
```

Ключ NVD необов'язковий. Якщо змінна середовища `NVD_API_KEY` непорожня, ключ передається в заголовку `apiKey`. У файлах проєкту ключ не зберігається.

## Формат звіту

У `stdout` друкується один JSON-об'єкт:

| Ключ | Значення |
|---|---|
| `cve_id` | Запитаний ідентифікатор |
| `variant` | Номер варіанта |
| `description` | Англійський опис або `null` |
| `vuln_status` | Статус NVD або `null` |
| `cvss_version` | `"3.1"` або `null` |
| `score` | Вибрана оцінка або `null` |
| `score_source` | Джерело вибраної оцінки або `null` |
| `vector` | Вектор вибраної оцінки або `null` |
| `rule` | `threshold`, `field`, `expected` за варіантом |
| `observed` | Значення `attackVector` у вибраній оцінці або `null` |
| `decision` | `not_found`, `rejected`, `insufficient_data`, `review` або `other` |

Стани `other` та `insufficient_data` не означають, що вразливість безпечна. Стан `review` означає лише відповідність навчальному правилу.

Коди завершення:

- `0`: звіт сформовано, зокрема зі станом `not_found` або `insufficient_data`;
- `1`: помилка отримання, читання чи перевірки даних (повідомлення в `stderr`);
- `2`: неправильні аргументи або номер варіанта.

## Структура

| Файл | Призначення |
|---|---|
| `main.py` | Аргументи командного рядка, отримання даних, повідомлення про помилки |
| `api_client.py` | Заголовки та один GET-запит до NVD |
| `analysis.py` | Перевірка відповіді, вибір оцінки й правило варіанта |
| `data/nvd_sample.json` | Синтетичний запис `CVE-2099-10001` для запуску без мережі |
| `tests/` | Тести аналізу, HTTP-клієнта та командного інтерфейсу |
